# VISUALIZATION ROUTER

Status: ACTIVE / OUTPUT ROUTER

Purpose: choose the visual form that makes the user's next understanding or decision easier.

Route by relationship:
- exact comparison / options / attributes → TABLE
- sequence / responsibility / state transition → FLOW or SWIMLANE
- system/components/dependencies → DIAGRAM
- quantities/trends/distribution → CHART
- screen interaction/layout → WIREFRAME or UI MOCKUP
- physical/geographic cluster/route → MAP
- hierarchy/taxonomy → TREE
- timeline/chronology → TIMELINE

Selection rule:
1. identify the decision or understanding the visual must support;
2. choose the smallest form that exposes the material relationship;
3. preserve source uncertainty and status visually when material;
4. do not make a decorative diagram when prose/table is clearer;
5. do not make a table when spatial/flow relationships are the point.

If multiple forms are useful, use one primary visual and at most one supporting form unless the user requests more.

`VISUAL COMPLEXITY != INSIGHT`
`PRETTY != USEFUL`
